# נוהל קבוע: עדכון גרסת האופליין של "אחותי כלה"

## מה חגית אומרת (המשפט הקבוע)
> **"עדכן את גרסת האופליין של אחותי כלה"**

אפשר להוסיף אחרי זה מספר גרסה או הערה, אבל לא חייבים.

תנאי מקדים אחד בלבד: הפרסום של הפרויקט **אחותי כלה** (achotikala.com) כבר בוצע,
כי הסנכרון מושך את האתר החי.

## מה הסוכן עושה בכל פעם (בדיוק, ובאותו סדר)

1. מריץ סנכרון מהאתר החי:
   ```bash
   node scripts/sync-offline-from-live.mjs --with-images
   ```
2. מוודא שהמניפסט נוצר: `public/updates/manifest.json` — מספר גרסה עלה,
   מספר הקבצים והחלקים סביר (בסיס ידוע‑תקין: 72 קבצים / 212 חלקים).
3. מוודא מקומית שכל החלקים נפתחים (אורך + checksum; חלקים ישנים גם XOR) — 0 שגיאות.
4. **לא נוגע** ב‑`public/downloads/achoti-kalah.html` (ה‑bootstrap).
   שינוי שלו מחייב את כל המשתמשות להוריד קובץ מחדש — נמנעים מזה.
5. מפרסם את האתר hagitmualem.com.
6. מוודא בייצור:
   - `https://hagitmualem.com/updates/manifest.js` — 200, מספר הגרסה החדש.
   - אימות מלא של כל החלקים וכל הקבצים המורכבים מול המניפסט החי.
7. מדווח לחגית: מספר גרסה, כמות קבצים/חלקים, ואישור שהמשתמשות לא צריכות לעשות כלום.

## מה קורה אצל המשתמשות
פותחות את אותו קובץ `achoti-kalah.html` כרגיל. הבדיקה מול השרת רצה ברקע,
מורידים רק קבצים שהשתנו, והגרסה מתחלפת רק אחרי אימות מלא. אין הורדה מחדש.

## מתי כן צריך הורדה מחדש של הקובץ
רק אם משנים את ה‑bootstrap עצמו (לוגיקת הטעינה/ההצפנה/האחסון).
במקרה כזה יש לומר זאת מפורשות לחגית ולשלוח לה את הקובץ המעודכן.

## אם משהו נכשל
- נכשל ב‑0% אצל משתמשת → בודקים גודל חלק בייצור מול הצפוי; תגובה זעירה (~70 בתים)
  = חסימת NetFree, ואז מקטינים chunk / מחזקים ערבול (ראה docs/OFFLINE-ARCHITECTURE.md).
- לא מפרסמים גרסה חדשה לפני שהאימות בסעיף 6 עבר.

## אימות פרסום (חובה)

אחרי כל פרסום להריץ:

```bash
node scripts/verify-offline-publish.mjs
```

הסקריפט מוריד את המניפסט החי ובודק לכל חלק: HTTP 200, מזהה קובץ, אינדקס ומספר חלקים,
אורך וחתימת DJB2. לאחר מכן הוא מרכיב מחדש כל קובץ, משחזר חתימת פתיחה אם נדרש,
ומאמת גם אורך, DJB2 ו-SHA-256 מלאים מול המניפסט.
בנוסף, סקריפט האריזה מאמת מקומית כל חלק (אורך + חתימת DJB2) *לפני* כתיבת המניפסט, ושומר גם את חלקי הגרסה הקודמת כדי שמשתמשות באמצע עדכון לא יקבלו 404.

סקריפט האריזה משתמש בנעילה בלעדית: אי אפשר להריץ שתי אריזות במקביל. בנוסף הוא אינו
ממחזר חלק קיים לפי הרישום בלבד — הוא קורא ומאמת בפועל את תוכן החלק לפני שימוש חוזר.
